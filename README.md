## 1. Scope of the reproduction package

This package accompanies the DOCX and PDF versions of the report. It contains all
experiment code, synthetic data, actual files of each format, per-repetition results,
source figures, the citation list and the code that builds the Word version. The
reference PDFs downloaded earlier are a separate package and are not copied here.

The data are synthetic data generated by the program, not field measurements or
official boundaries. The results in `experiments/results` were actually run in the
environment recorded in `experiments/results/environment.json`. They are not yet
considered results the group ran on its own machine.

A second run, made in Docker on the group's machine, is stored in
`experiments/results_group` with its log in `experiments/run_group.log`. The report
still uses `experiments/results`. The last line of that log shows the output path
`results_nhom`, the directory's name at run time; the log was left unedited.

## 2. Rerunning the experiments

### With Docker (recommended; installs nothing on the host)

    docker compose build
    docker compose run --rm experiments python run_experiments.py --output results_reproduced --repeats 5

The `experiments` service uses the pinned packages, no network, and limits of 8 CPUs
and 8 GiB. If your user ID is not 1000, set `HOST_UID` and `HOST_GID`.

### With a virtual environment

Use Python 3.12. From the `experiments` directory:

    python3 -m venv .venv
    source .venv/bin/activate
    python -m pip install -r requirements.txt
    python run_experiments.py --output results_reproduced --repeats 5

On Windows, use `.venv\Scripts\activate` to activate the environment. Do not overwrite
the original results when comparison is needed. See `experiments/README.md` for the
full conditions on data, compression, cache, fsync, geometry checks and limitations.

The package versions in `requirements.txt` are the real versions of the environment
that ran, recorded on November 2, 2026. If your environment uses other versions,
another operating system, or cannot install a version, record the change and keep the
metadata of the new run; times are not expected to match exactly.

## 4. Rebuilding the figures

The two figure scripts use NumPy and Matplotlib; the report's plotting environment
uses NumPy 2.3.5 and Matplotlib 3.10.8. This is the publishing environment, separate
from the GIS environment with its own pinned dependencies.

    docker compose run --rm publish sh -c "python theory_examples.py && python figures/draw_theory_figures.py && python figures/draw_result_figures.py"

Without Docker, use a second virtual environment:

    python -m pip install -r requirements_artifacts.txt
    python theory_examples.py
    python figures/draw_theory_figures.py
    python figures/draw_result_figures.py

The results script reads the saved tables and does not rerun the benchmark. PNG files
are 300 dpi; SVG files keep vector figures for resizing or use in slides.

## 5. Rebuilding the Word document and exporting a PDF

The source content is stored under `sources`. The combined version is
`sources/report_content_complete.json`. The individual parts and `bibliography_report`
are the inputs of `build_report_docx.py`. The program needs python-docx, lxml, and
pandoc on the PATH to create native Word OMML equations.

    docker compose run --rm publish python build_report_docx.py
    docker compose run --rm publish soffice -env:UserInstallation=file:///tmp/lo --headless --convert-to pdf Spatial_Object_Representation_Report.docx

Check the layout again after changing fonts, content or the export software. The
delivered Vietnamese report was checked at 23 pages in its PDF version; the page count
may differ on other machines and in this English version.

`build_report_content.py` under `sources` is the code that originally built the
experimental part from the result tables. To update the content, edit the JSON or the
Word version deliberately; do not rerun every script blindly. Changes to conclusions
must rest on the measured figures of the corresponding run.

For theoretical evidence, the checked source is Chapter 2 “Representation of Spatial
Objects”, pp. 29–67 by printed page numbers in Spatial Databases: With Application to
GIS (Rigaux, Scholl and Voisard, 2002). It uses the excerpt `upload/page59-97.pdf` of
the previous research pass; the re-downloaded file with the suffix (1) was not used
because it was inaccessible. PDF page numbers in the excerpt differ from printed page

If you rerun `sources/build_report_content.py` to refresh the content, run

## 6. Interpreting the results within scope

- E2 measures a complete read to id, class and Shapely geometry, not metadata only.
- The GeoParquet ZSTD file is already compressed internally; gzip6 is a separate layer.
- Warm operating system cache; writes without fsync; durable writes are not measured.
- TopoJSON has quantization and simplification disabled; it may still drop collinear vertices.
- MVT involves clipping and quantization; it is not equivalent to a lossless complete copy.
- The MVT Hausdorff is discrete, without densification, in Mercator coordinate meters.
- The MVT area difference is summed per object, not computed after a union of the whole
  domain; error is measured on the full domain while viewport time is separate.
- There are no measurements of HTTP, browsers, drawing time, peak memory or cold cache.
- The median and Q1–Q3 of five runs are descriptive statistics, with no significance testing.
