# Experiments on the Representation of Spatial Objects

This code supports the Group 1 report on Chapter 2. The data are **synthetic data generated by the program**, not field measurements or official administrative data. The figures in the results directory were measured by an actual run in the environment recorded in results/environment.json.

## Rerunning

Requires Python 3.12 and the packages in requirements.txt.

    python3 -m venv .venv
    source .venv/bin/activate
    python -m pip install -r requirements.txt
    python run_experiments.py --output results_reproduced --repeats 5

By default this runs 100, 1,000 and 10,000 objects; MVT uses 10,000 objects at zoom 11, 13 and 15. A quick installation check:

    python run_experiments.py --output quick_check --scales 100 --mvt-features 100 --zooms 13 --repeats 1

The quick_check results do not replace the report's 5-repetition result set.

## Data and comparability

- 2D polygons, coordinate system OGC:CRS84, longitude then latitude order.
- Data domain [105.75, 20.95, 105.87, 21.07], in degrees.
- Grids of 10×10, 25×40 and 100×100 cells; each ring has 17 coordinate pairs including the closing point.
- Interior shared edges have 4 segments and a zigzag offset of 6% of the cell size; the outer boundary is a rectangle. The same edge is taken from the same coordinate sequence to guarantee an exact match. The design limits confusion between the benefit of arc sharing and the removal of collinear vertices.
- Input coordinates are rounded to 12 decimal places. No simplification in E2.
- The two attributes id and class are integers; id is unique, class=(column+row)%5. No index column is added to GeoParquet.
- The order of configurations is shuffled within each repetition using seed 20261102. The geometry has no random component.

## E1 Shared boundaries and updates

Two adjacent polygons are represented in GeoJSON and TopoJSON:

1. Exactly matching boundary: checks the number of shared arcs and the touch relation after conversion.
2. A gap created by shifting the second polygon 0.000001 degrees in longitude; TopoJSON quantization is disabled, to test whether the format repairs the gap by itself.
3. Moving a mid-boundary vertex of the shared edge by 0.0001 degrees: editing polygon A alone in GeoJSON, or editing the arc referenced by both A and B in TopoJSON.

TopoJSON may drop collinear vertices while keeping the geometric point set unchanged. Before the arc edit, the code reinserts the intermediate vertices so that both edits use the same position; the two endpoints connecting to other arcs stay fixed. The touch relation is measured on the input coordinates. Illustrative distance, length and area are computed after projecting to UTM zone 48N, EPSG:32648.

E1 is a controlled example; it does not prove that every arc update keeps the geometry valid. The code checks the geometry after this specific operation.

## E2 Size and complete-dataset processing paths

Five configurations:

1. GeoJSON: compact UTF-8 JSON, Python round-trip floats.
2. TopoJSON: topojson; prequantize=False, topoquantize=False, presimplify=False, toposimplify=False. Arcs store real coordinates, with no quantization transform.
3. KML: namespace http://www.opengis.net/kml/2.2 per KML 2.3; Schema/SimpleField of type int for id/class; Polygon without altitude, clampToGround. Coordinates use Python's round-trip representation.
4. GeoParquet-NONE: WKB, schema 1.1.0, compression=None, index=False, row group 1,000.
5. GeoParquet-ZSTD: same schema and data, changing only the column codec to the library's default ZSTD.

**The common target after reading** is a complete list of records with id int, class int and Shapely geometry. No format is measured at metadata level while another is measured at geometry level.

File bytes are measured, and an external gzip level 6 compression, mtime=0, is added for each file. External gzip and the ZSTD codec inside Parquet are separate factors. The gzip column of GeoParquet-ZSTD is a double compression measured for transparency, not an operational recommendation.

Timing procedure:

- Data are created before the timed interval.
- One untimed write-read correctness-check pass.
- One untimed write-read warm-up pass.
- Five repetitions, with the configuration order shuffled in each.
- gc.collect() outside the timed interval; clock time.perf_counter_ns().
- Writing covers building the target structure, encoding, writing and closing the file; **no fsync**. Not to be interpreted as durable write latency to the device.
- Reading covers opening/reading the file, decoding and creating all Shapely geometry.
- **Warm operating system cache**, not cleared; a read follows a write of the same configuration.
- The median and Q1–Q3 of the five runs are descriptive statistics; no significance testing.
- Library/implementation differences are part of the processing path. No inherent speed ranking of all format implementations is implied.

Checks: complete objects, unique and matching ids, class matches and reads back as int, valid/non-empty geometry, count of topologically equal geometries, maximum Hausdorff and area deviation. The check threshold is 1e-12 degrees; the actual deviation is stored, not replaced by the threshold. GeoParquet metadata is kept in JSON.

## E3 Vector Tiles and viewport

- The same 10,000 polygons are projected to EPSG:3857 before the tile build interval.
- The XYZ Web Mercator scheme is chosen for the test; this does not claim that MVT requires every system to use Web Mercator.
- Zoom 11, 13, 15; extent=4096; clip buffer=0; no simplification.
- Polygons are clipped at tile boundaries; Polygon/MultiPolygon fragments with positive area are kept; encoding uses mapbox-vector-tile.
- The viewport is at the center of the domain, 1/4 of its width and 1/4 of its height; its area is 1/16 of the domain.
- Full-domain tiles and tiles intersecting the viewport are counted; total raw bytes and total gzip6 of each tile. This is the number of tiles to read under the selection policy, **not an HTTP measurement**.
- Decoding to Shapely geometry in Mercator. A global integer grid is used before conversion to floats so that the same grid node on two tiles has exactly the same float value.
- Fragments with the same id are merged; completeness of ids/attributes, validity, Hausdorff and total symmetric difference area are checked.
- Hausdorff uses the discrete GEOS/Shapely measure with no added densification. The area difference ratio is the total area of P_i symmetric difference P_i_reconstructed per object, divided by the total source object area; it is not the difference between two union outlines of the whole map. A region misassigned between two cells can contribute to the error of both objects.
- The number of fragments, unique ids and objects actually intersecting the viewport are recorded separately.
- Tile build time covers STRtree, clipping, encoding, writing and producing the gzip measurement; measured only once, as operational information.
- Full-domain and viewport decoding time: one warm-up, five repetitions; covers local reading, protobuf decoding, geometry creation and coordinate conversion.
- No measurement of network, browser, interaction time or map drawing.
- MVT involves clipping and quantization, so it is not placed in E2 as an equivalent lossless complete copy.

## Results

- environment.json: environment, versions, times, cache and limitations.
- datasets.json: grids and geometric configuration.
- e1_topology.json: shared boundary, gap, update.
- e2_raw_timings.csv: every E2 measurement.
- e2_summary.csv/json: bytes, median/IQR, metadata, read-write checks.
- e3_raw_timings.csv and e3_summary.csv/json: MVT.
- e3_configuration.json: domain, viewport, CRS, tile scheme, clipping.
- data: actual files of each format and tiles.
